BROCODE / ARCHITECTURE PROPOSAL

A browser specialist agents can trust—not a directory of one-off scripts.

Keep the working engine. Give it one guarded runtime, a real ACP interface, reusable procedural memory, and evidence-backed outcomes.

What needs fixing

OWNERSHIP

CLI preflight can be bypassed by Python callers. There is no shared task lifecycle or cross-process profile lease.

TRUTH

“Completed” currently means the agent returned—not that the requested outcome was verified. Documentation and egress behavior disagree with the code.

BOUNDARIES

Uploads, datasets, evidence, personal facts, and code are mixed together. Hardcoded browser scripts bypass the intended agent.

BASELINE

No Git repository, dependency manifest, or test suite found. Most of the 3.3 GB is browser state and media; application code is small.

One runtime. Three entrypoints.

T3 / ACP clients → ACP stdio ┐
Other agents → optional MCP ├→ task runtime → browser-use worker
Humans / scripts → CLI / API ┘

Runtime owns policy · memory · preflight · profile lease · evidence
Worker owns observation · adaptive browser actions · scoped recovery

ACP means Agent Client Protocol. Use its official Python SDK. Keep browser-use and the current Chrome profile initially; do not change frameworks and protocols in the same rewrite.

The non-negotiable contract

  • A request describes the outcome, inputs, authority, permitted files, and budgets—not selectors.
  • A result reports status, structured data, evidence, and uncertainty—not just prose.
  • One owner per authenticated profile, across every entrypoint. Competitors get PROFILE_BUSY.
  • Submissions require scoped authority. Denial or lost approval means no mutation.
  • Uncertain submissions are reconciled against site records, never blindly repeated.

Memory is a playbook, not a script

playbooks/indeed-apply/PLAYBOOK.md

Goal + required inputs + permitted domains + authorization + procedure + verification + source run + last-verified date.

Observe the current page and adapt. No hardcoded selectors, stale applicant facts, credentials, or implicit permission to submit.

Store sanitized procedures in Markdown, private facts separately, and task history in SQLite. Retrieve relevant knowledge before acting. After a verified run, save a draft learning; approve it before promotion to trusted procedure. A literally empty file cannot preserve workflow knowledge.

Prove the T3 boundary first

The installed T3 build includes a local acpRegistry provider path. Proposed command: brocode acp. Registration and runtime handshake are not yet tested.

The first gate is a clean SDK-backed handshake, streamed progress, permission denial, cancellation, and successful child-task targeting. Confirm actual provider/model IDs from T3’s live catalog. ACP stdout must contain protocol frames only; browser logs stay on stderr.

Cleanup without losing working state

PRESERVE

Chrome profile, secrets, resumes, successful-run evidence, and the browser/egress/captcha infrastructure. Back up before relocation.

REFACTOR

Extract brocode.py into a small package: runtime, worker, contracts, store, memory, adapters, and infrastructure. Keep compatibility until callers migrate.

ARCHIVE

Hardcoded Glassdoor and legacy home workflows; user datasets stay private. Never execute old scripts as agent tools.

DELETE LATER

Generated bytecode, proven stale PID markers, obsolete wrappers after migration, and routine media under an approved retention policy. No sweeping deletion.

Implementation sequence

  1. Protect and baseline

    Inventory, backups, secret scan, lockfile, source-only Git, truthful docs.

  2. Prove ACP ↔ T3

    Fake worker first. Handshake, progress, approval, cancel, disconnect, delegation.

  3. Unify task execution

    Shared preflight, exclusive profile ownership, durable statuses, worker events, bounded shutdown.

  4. Enforce authority and verification

    Audit all action paths—including keyboard, scripts, and batches—for approval bypasses.

  5. Add useful memory

    Sanitize the Indeed procedure, separate facts, track provenance, test stale knowledge.

  6. Finish caller coverage

    MCP if needed, T3-owned scheduling, retention, then retire legacy entrypoints.

Definition of done

Other agents can delegate a goal; cancel it safely; inspect durable results; reuse a proven procedure; and never create loose home files, share an active profile, fabricate required facts, or report an unverified submission as success.
